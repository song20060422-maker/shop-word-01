# 09 · 缺陷修复流程

## 流程（发现 → 闭环）

1. **登记**：`docs/review_records.md` 记录问题、复现步骤、期望/实际、违反的 BR/AC、版本哈希。
2. **复现**：先写**失败的回归测试**（能稳定复现），跑出真实失败输出。
3. **定位**：根因到代码行级；查错误日志（`log/zap-error.log`、DB 慢查）与并发时序。
4. **修正**：最小改动；不得顺手重构无关代码；涉及状态机遵守 `08-flow-codegen.md`。
5. **复测**：回归测试转绿 + 全量 `go test ./shop/... -count=1` + 验收脚本受影响套件；exit 0。
6. **留痕**：回填 review_records（根因、修正文件、复测命令与输出）；`docs/events.md` 登记事件。
7. **提交**：`[fix][版本][T#] 描述`；审计问题引用其编号（如 I-18）。

## 教训库（历史缺陷 → 固化约束）

| 缺陷 | 固化约束 |
|---|---|
| 清扫器期望值断言错误 | 断言写业务语义（"全部超时单被关闭"），不写魔法数字 |
| 契约委派绕过路由组角色门禁 | 委派 handler 内必须复核角色（05-security） |
| 覆盖率 profile 拼接被审计判不合规 | 只用单命令生成（05-quality） |
| 验收脚本端口被其它配置段污染 | 解析限定 shop 段（04-config） |
| 渠道重试并发重复发起退款 | 事务级行锁闸门 + 调用计数断言（08 模式 C） |
| 记款 DB 错误一律误报重复支付 | 唯一键冲突才判重复（08 模式 B） |
| GBK 控制台输出崩溃 | 入口强制 UTF-8，不依赖环境变量（07-conflict） |

## 红线

- 修不了的问题如实标注"未解决+原因"，不得静默放过。
- 不为让测试变绿而改测试语义（弱化断言=作假）。
