你是一名**独立测试 Agent**（独立会话上下文，与开发会话无共享记忆），对一个小型电商服务端（题目01：订单交易、发货与售前退款）的新交付版本执行独立测试并留档。

被测对象：gin-vue-admin（git 分支 `dev/01-shop`，以 `git rev-parse HEAD` 实测哈希为准，直接测试当前工作区）。

题面依据（只读）：`references/` 下的 `需求文档-Shop商城小型交易系统.md`、`business-rules.md`、`assumptions-v1.0.md`。

交付说明：`server/shop/docs/DELIVERY.md`。

你的任务：

1. 读题面（业务规则 BR 与验收条件），列出你要核验的测试点。
2. 独立构建与测试（本机 MySQL 3307 已就绪，root/root）：
   - `gofmt -l shop`；`go vet ./shop/...`；`go build ./shop/...`
   - `go test ./shop/... -count=1`（真实 MySQL 集成测试）
3. 抽查实现与题面的一致性（读关键 service 代码：order/payment/refund/shipment），重点：
   10分钟超时释放幂等、支付通知验签与重复拒绝、迟到支付进异常、退款与发货互斥恰一结果、
   渠道失败重试恢复恰一次、发货仅一次、运营聚合四类记录。发现任何不符点如实记录为缺陷（若有）。
4. 将结果写入两个文件（只允许新建这两个文件，不得修改任何其他文件）：
   - `agent-test/agent-test-report-<日期>-<短哈希>.md` —— 独立测试报告：
     被测版本（git rev-parse HEAD）、环境、执行命令与原始退出码、测试点清单与结论、发现的缺陷（或"无"）、总体结论。
   - `agent-test/session-<日期>-<短哈希>.md` —— 会话记录：
     按时间列出你实际执行的每一步（命令、工具动作、结果摘要）。
5. 报告必须基于真实执行结果，严禁虚构通过；任何失败都要如实写明。

最后返回一段简短总结：测试结论（通过/失败数）、发现的缺陷列表、报告文件路径。
